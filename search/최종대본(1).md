## <1페이지> 
- 안녕하세요, 인공지능프로그래밍 팀프로젝트 5조 최종발표를 맡은 강승관이랑 함기연 입니다. 저희 조의 프로젝트 주제는 '머신러닝 기반 악성코드 탐지 시스템'입니다.

## <2페이지> 
- 오늘 발표 목차입니다. 프로젝트 개요, 데이터셋, 모델선정, 학습 파이프라인, 모델 학습, 예측, 평가, 시각화 도구, 결론 순이고 제가 학습 파이프라인까지 / 그리고 기연님께서 그 이후 발표할 예정입니다.

## <3페이지> 
- 먼저 배경입니다. 최근에는 서비스형 악성코드, 즉 마스 가 대중화되고 멀웨어 공급망 공격이 늘면서, 신종 악성 바이너리가 대량으로 유포되고 있어 공격 초기 단계에서 차단할 필요성이 커졌습니다. 저희가 노린 대상은 윈도우 기반 엔드포인트, 그중에서도 랜섬웨어나 자격 증명 탈취 같은 주요 악성 패밀리입니다. 핵심 아이디어는, 파일을 직접 실행하지 않고 실행파일 구조 안의 API 호출 패턴만 정적으로 추출해, LightGBM 모델로 악성 여부를 빠르게 1차 판별하는 것입니다.

## <4페이지> 
- 그럼 기존 방식과 무엇이 다른지 보겠습니다. 첫째, 서명 기반 탐지입니다. 해시 매칭 방식인데, 이는 코드가 조금만 바뀌어도 탐지를 우회합니다. 변종이나 제로데이에 구조적으로 취약하단 한계가 있습니다. 둘째, 샌드박스 동적 분석입니다. 정밀하긴 하지만 시스템 부하가 크고 분석이 느립니다. 또한 Sleep 같은 가상화 우회 기법에도 약합니다. 저희 모델은 이 둘 사이의 초경량 1차 방어선입니다. 단순 식별값이 아니라 API 구조를 추론하기 때문에 외형 변형에 대응할 수 있고, 실행하지 않는 환경에서 대량의 파일을 빠르게 스크리닝 후 걸러내어 무거운 동적 분석의 부담을 덜어줍니다.

## <5페이지> 
- 그러면 왜 하필 API 정적 분석이냐, 다른 접근법들과 비교해 봤습니다. CNN으로 파일을 이미지화하는 방식은 더미 데이터를 넣으면 픽셀이 왜곡되고, 결정적으로 블랙박스라 모델이 왜 그렇게 판단했는지 해석이 안 됩니다. 실행 후 API 시퀀스를 보는 행위 기반 동적 모델은 안티 샌드박싱을 탑재한 최신 멀웨어에 제한적입니다. 반면 저희가 택한 IAT 정적 분석은, 선언된 API 이름 자체가 곧 의도된 행위를 대변하기 때문에 예측 근거를 투명하게 해석할 수 있습니다. 또 추출 로직이 정형화돼 있어서, 학습할 때 쓴 파싱 로직을 추론 엔진에서 왜곡 없이 그대로 재사용할 수 있다는 장점도 있습니다.

## <6페이지> 
- 저희가 사용한 데이터셋입니다. 파일 샘플은 약 4만 7천 개, 윈도우 API 피처는 1,000개입니다. 그런데 보시면 정상 대 악성 비율이 1 대 23.7로 굉장히 불균형합니다. 악성이 96%, 정상이 4%인 것을 알 수 있습니다.

## <7페이지> 
- 이렇게 데이터가 불균형하면, 전부 악성이라고 찍기만 해도 정확도가 96%가 나오기 때문에 단순 정확도는 지표로 쓸 수 없습니다. 그래서 저희는 주요 지표를 악성 Recall과 정상 Recall을 더해서 2로 나눈 균형 정확도로 잡았습니다. 그리고 추가적인 보조 지표로 불균형에 강한 상관계수인 MCC를 함께 봤습니다.

## <8페이지> 
- 본격적인 실험에 앞서 저희는 전체 데이터를 학습 80%, 테스트 20%로 나눴습니다. 학습 80%는 피처 개수나 불균형 비율, 모델 선택 같은 실험에 쓰고, 테스트 20%는 최종 테스트용으로 따로 떼어 뒀습니다. 모델은 LightGBM을 썼고, 피처를 몇 개를 사용할지와 데이터셋 비율 후보들을 조합했습니다. 교차 검증 기법으로는 Stratified K Fold를 사용했고, 이 방식은 데이터를 나눌 때 원본의 정상, 악성 비율을 그대로 유지해 불균형 데이터에서도 평가가 공평해져 안정적으로 비교가 가능합니다. 이제 학습 후 평가표를 보시면 뚜렷한 경향을 볼 수 있는데 피처 개수가 많아질수록, 그리고 악성과 정상 비율이 1 대 1에 가까워질수록 균형 정확도가 높아지는 것을 확인할 수 있습니다.

## <9페이지> 
- 그럼 피처를 많이 쓰면 무조건 좋아지나 싶지만 / 피처 개수별로 보면, 50개를 초과하면 성능 향상은 미미한 반면 차원의 저주(Curse of Dimensionality)로 인한 과적합(Overfitting) 위험과 추론 시간만 증가하기 때문에, 최적의 효율을 내는 50개로 피처를 고정했습니다.

## <10페이지> 
- 피쳐를 50개로 고정한 채, 리샘플링 비율에 따른 평가표입니다. 표에서 알 수 있듯이, 원본 비율에서 정상 Recall이 매우 낮은걸 알 수 있습니다. 그래서 저희 목표는, 정상 Recall은 회복하되 악성 Recall을 과도하게 희생하지 않는 점을 찾는 것이었습니다.

## <11페이지> 
- 그 결과를 비율별로 정리한 표입니다. 원본 1 대 23은 정상 Recall이 약 0.5로 너무 낮습니다. 반대로 1 대 1까지 균형을 맞추면 정상 Recall은 약 0.87까지 많이 오르지만, 합성 정상 샘플을 약 2만 8천 개나 만들어야 하고 악성 Recall도 떨어집니다. 그래서 저희는 1 대 4를 채택하여 합성 부담을 줄이고, 악성 Recall을 어느정도 높게 유지하면서 균형 정확도 0.9를 확보했습니다.

## <12페이지> 
- 최종적으로 사용할 모델 선택입니다. 기존에 저희는 피처중요도로 불필요한 피쳐를 걸러내고, OOB를 검증 데이터로 활용할 수 있는 랜덤 포레스트를 선택했었는데 / 지난 중간 발표 때 교수님께서 랜덤포레스트를 고른 명확한 이유가 있으면 좋겠다는 말씀을 하셔서, 저희는 몇 개의 모델을 더 선정하고 성능을 확인하기로 했습니다. RandomForest, LightGBM, XGBoost 세 모델을 같은 조건에서 비교했는데, 그래프처럼 튜닝 전후 모두 세 모델의 전반적인 균형 정확도(Balanced Accuracy)는 비슷한 수준이었습니다. 성능이 비슷하다면, 그중에서도 추론 속도가 가장 빠르고 실제 오탐률 방지에 중요한 '정상 Recall'이 가장 높게 나온 LightGBM을 최종 모델로 선택하는 것이 합리적이라고 판단했습니다.

## <13페이지> 
- 마지막으로 학습 파이프라인입니다. 전체 구조는 위 흐름도처럼 간단합니다. 원본 데이터로 LightGBM 모델을 학습시킨 다음, 그 모델을 파일로 저장해 두고, 실제로는 이 저장된 모델을 불러와 실시간으로 예측합니다. 과정은 크게 두 단계로 나뉩니다. 먼저 학습 단계에서는, 앞서 설명한 API 기반 Feature Vector를 입력값 X로, 정상·악성 여부를 정답 라벨로 두고 데이터를 8 대 2로 나눕니다. 이때 미리 분리해 둔 80%의 학습 데이터에만 리샘플링을 적용하여 Data Leakage(데이터 누수)를 완벽히 차단했습니다. 이후 이렇게 준비된 데이터로 LightGBM 분류 모델을 학습합니다. 예측 단계에서는, 새로운 PE 파일이 들어오면 그 파일의 Import API를 추출하고, 학습할 때 저장해 둔 API 목록을 기준으로 똑같이 Feature Vector를 만듭니다. 이걸 학습된 모델에 넣어 정상인지 악성인지 분류하고, 예측 확률을 신뢰도로 함께 보여줍니다.
이어지는 모델 학습부터는 기연님께서 설명드리겠습니다.
