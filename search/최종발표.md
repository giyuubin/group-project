# 악성코드 예측 모델
## 1. 개요
### 1.1 프로젝트 정의
- <img width="1024" height="559" alt="image" src="https://github.com/user-attachments/assets/28aceee5-fa2c-4678-86cb-8af1025cdca4" />

- 본 프로젝트는 Windows 실행 파일(.exe)의 PE(Portable Executable) 구조 내에서 파일의 직접적인 실행 없이 API 호출 패턴을 정적으로 추출하고, 이를 학습한 LightGBM 기계학습 모델을 통해 악성 여부를 사전 판별하는 파이프라인 구축을 목표로 한다.
  
### 1.2 기존 보안 시스템과의 차이점
- 본 프로젝트의 정적 API 분석 모델은 기존 백신 시스템을 대체하기보다는, 두 주요 탐지 기법 사이의 사각지대를 보완하는 '초경량 1차 방어선(Pre-filter)' 역할을 수행한다.
  - 서명 기반(Signature-based) 탐지의 구조적 한계 보완: 기존 해시(Hash) 매칭 방식은 코드가 소폭 변경되어도 탐지를 우회할 수 있다. 본 모델은 단편적인 식별값이 아닌, 실행 파일의 뼈대인 'API 호출 구조(IAT)'와 '정상 소프트웨어 고유 패턴의 부재(Absence)'를 기계학습으로 추론하여 외형 변형에 대한 보완재로 작용한다.
  - 동적 분석(Dynamic Analysis)의 리소스 병목 해소: 샌드박스(Sandbox) 기반의 동적 분석은 고도화된 위협 식별에 유리하나, 시스템 부하와 분석 지연(Delay)이 발생할 수 있다. 본 정적 모델은 파일을 실행하지 않는 환경에서 대량의 파일을 고속으로 스크리닝하여, 동적 분석 시스템으로 인입되는 부하를 효과적으로 경감시키는 게이트웨이 역할을 한다.
    
## 2. 연구 배경 및 목적
### 2.1 연구 배경
- <img width="1024" height="559" alt="image" src="https://github.com/user-attachments/assets/0b5c7175-0e7e-41dc-bc81-30131510f783" />

- 최근 멀웨어 공급망 공격 및 MaaS(Malware-as-a-Service)의 대중화로 인해 다수의 신종 위협 바이너리가 유포되고 있다. 파일 시스템 내부로 악성 코드가 진입하는 첫 관문(Initial Access)에서 위협을 선제적으로 탐지하기 위한 경량화된 엔드포인트 정적 진단 기술이 요구되고 있다.
  
### 2.2 위협 모델 정의
- <img width="1024" height="572" alt="image" src="https://github.com/user-attachments/assets/3c2739a5-f176-44d4-9b7a-532e1fb084bd" />

- 공격 대상 시스템: Windows OS 기반 엔드포인트 시스템 및 사용자 자산.
- 공격자 프로파일 및 시나리오: 사용자 시스템에 최초 침투하여 권한 상승, 자격 증명 탈취, 데이터 암호화 및 유출을 시도하는 주요 악성 패밀리.
## 3. 관련 연구 및 선행 연구
### 3.1 다른 PE 기반 분류 접근법과의 비교
- 바이너리 이미지화 기반 딥러닝 (CNN): 전체 바이트를 2D 이미지로 변환하는 방식은 더미 데이터에 의해 픽셀이 왜곡될 수 있으며, 의사결정 과정의 명확한 해석이 어렵다(Black-box).
- 행위 기반 동적 샌드박싱 모델: 실행 후 API 시퀀스를 모니터링하는 방식은 샌드박스 우회 기법(Sleep 등)을 탑재한 최신 멀웨어에 제한적일 수 있다.
  
### 3.2 본 프로젝트가 IAT 기반 정적 분석을 택한 이유
- <img width="1024" height="559" alt="image" src="https://github.com/user-attachments/assets/67c9f8fd-2664-401c-942c-2f32d376b861" />

- 보안 도메인 지식과의 연계 (Explainability): PE 파일의 IAT(Import Address Table)는 실행 파일이 운영체제 커널의 기능을 호출하기 위해 선언한 윈도우 API들의 이정표이다. API 이름 자체가 파일의 의도된 행위를 대변하므로 예측 근거를 비교적 명확하게 해석할 수 있다.
- 일관된 파이프라인 구조: 추출 로직이 가볍고 정형화되어 있어, 모델 학습 시 파싱 로직을 실시간 추론 엔진에 동일한 형태로 적용할 수 있다.
  
## 4. 데이터셋
### 4.1 출처 및 수집 방법
- <img width="922" height="159" alt="image" src="https://github.com/user-attachments/assets/6e2eee16-5218-4485-9a25-a84d62cd6236" />

- 원천 출처:
  - Kaggle 플랫폼에 공개된 Angelo Oliveira의 "Malware Analysis Datasets: Top-1000 PE Imports" 데이터셋을 활용하였다.
  - 이는 보안 학술 연구용으로 널리 인용되는 데이터로, 수만 개의 PE 파일에서 IAT(Import Address Table)를 파싱하여 가장 빈번하게 호출되는 상위 1,000개의 윈도우 API를 선별 및 정제해 둔 고품질 데이터셋이다.
- 표본의 다양성:
  - 글로벌 멀웨어 공유 인프라(VirusShare 등)에서 수집된 실제 위협 샘플들과, 클린 환경의 정상 유틸리티 표본이 혼합되어 실전 방어 환경을 적절히 모사하고 있다.
- 데이터 인코딩 구조 (Feature Representation):
  - <img width="1886" height="707" alt="image" src="https://github.com/user-attachments/assets/e97afe4b-c8e0-40f8-9375-8eb310209448" />

  - 원본 데이터는 각 행(Row)이 개별 실행 파일(Hash)을, 열(Column)이 상위 1,000개의 주요 API를 나타낸다.
  - 해당 파일이 특정 API를 호출하면 1, 그렇지 않으면 0으로 기록된 희소 행렬(Sparse Matrix) 형태를 띠며, 이는 본 프로젝트의 이진 피처(Binary Feature) 학습 전략과 완벽히 부합한다.
- 레이블 객관성:
  - 각 샘플의 악성/정상 라벨은 다중 백신 검증 엔진인 VirusTotal의 교차 검증 점수를 기반으로 하여 일정 수준의 레이블 객관성을 확보하였다.
  
### 4.2 규모 및 클래스 분포
- <img width="803" height="658" alt="image" src="https://github.com/user-attachments/assets/44e10bdd-9009-47fe-a6c1-8e555e3e0190" />

- 총 샘플 규모: 47,580개 (결측 데이터 없음)
- 초기 피처 공간: 등장 빈도 상위 1,000개의 Windows API 함수 사용 여부 (0/1 이진 인코딩)
- 클래스 불균형 비율: 정상 대 악성 = 약 1 : 23.7 (정상 1,929개 / 악성 45,651개)
  - 인더와일드(In-the-wild) 환경의 위협 유포 특성을 반영하듯, 수집 데이터셋 내에 정상 샘플 대비 악성 샘플이 다수 포진된 구조적 불균형이 존재한다.
  - 정상 표본(1,929개)은 백신 검증을 거친 시스템 바이너리 및 유틸리티로 구성되어 정상 군집으로서의 기본 요건을 충족하는 것으로 전제한다.
  - 이러한 1:23.7의 불균형 분포는 모델이 다수 클래스(악성)에 편향되어 정상 파일을 악성으로 오인(False Positive)할 가능성을 높인다.
  - 이는 단순한 알고리즘 튜닝만으로는 해결이 까다로운 데이터 구조적 한계이므로, 본 프로젝트는 향후 '오버샘플링(SMOTE) 및 임계값(Threshold) 최적화'를 도입하여 정상 파일의 결정 경계를 보정하고 오탐률을 제어하는 주요 근거로 삼는다.
