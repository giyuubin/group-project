# [분석 보고서] 정적 스캐너 악성코드 탐지 결과 분석

## 1. 탐지 결과 요약 (Detection Summary)
* **대상 파일:** `malware_test.exe`
* **타겟 피처(API) 매핑:** **0개 / 50개 (0%)**
* **탐지 임계값 (Threshold):** 85% (0.85)
* **최종 악성 확률 (Probability):** **94.92%**
* **최종 판정:** **🚨 악성코드 탐지 및 격리 조치**

---

## 2. 핵심 이상 현상 (Key Anomaly)
가장 주목해야 할 특이점은 **모델이 추적하는 50개의 핵심 API가 파일 내부에서 단 한 개도 발견되지 않았음(0개)에도 불구하고, 악성 확률이 94.92%로 매우 높게 도출되었다는 것**이다. 

일반적인 룰 기반(Rule-based) 백신이나 단순 선형 회귀 모델이었다면 특징이 없으므로 '0% (정상)'으로 판단하여 미탐(False Negative)이 발생했을 상황이다.

---

## 3. 기술적 원인 분석 (Technical Root Cause)

### 가. 악성코드의 고도화된 은닉 기법 (Packing/Obfuscation)
* 정상적인 Windows 실행 파일(`.exe`)은 운영체제 환경에서 동작하기 위해 메모리 할당이나 프로세스 종료 등 최소한의 기본 API를 IAT(Import Address Table)에 반드시 포함해야 한다.
* 탐지된 API가 '0개'라는 것은 파일이 실행 코드를 숨기기 위해 **패킹(Packing, 예: UPX, Themida 등)을 수행했거나, IAT 자체를 파괴 및 난독화하는 심각한 회피 기법**을 적용했음을 물리적으로 의미한다.

### 나. LightGBM 모델의 비선형 역추론 (Non-linear Inference)
* 본 정적 스캐너에 탑재된 LightGBM 알고리즘은 단순히 특정 악성 API의 '존재 유무(1)'만 가중치로 합산하는 것이 아니다. 
* 모델은 방대한 학습 과정을 통해 **"정상 파일이라면 무조건 가지고 있어야 할 기본 런타임 API조차 모두 결측치(0)를 보이는 현상은, 고도로 훈련된 악성코드의 패킹 행위이다"**라는 패턴을 스스로 학습했다.
* 즉, '특징의 부재(Absence of features)' 자체를 강력한 악성 징후로 식별하여 94.92%라는 높은 위험도를 산출해 낸 것이다.

---

## 4. 결론 (Conclusion)
본 시연 결과는 해당 정적 스캐너 모델이 단순한 특징 매칭(Signature Matching)의 한계를 넘어섰음을 증명한다. **악성코드 제작자가 분석을 방해하기 위해 API를 완전히 숨긴 기형적인 데이터 구조(0/50)를 입력받았음에도, 이를 역이용하여 정확하게 위협(94.92%)으로 분류해 내는 뛰어난 추론력과 방어 성능**을 보여준다.
